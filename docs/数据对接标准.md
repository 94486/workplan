# 龙猫工作统计台 — 数据对接标准（供外部程序参考）

本文档是**数据标准**：你的计时软件（或任何程序）只要按本标准生成 JSON，就能通过「文件导入」或「推送接口」把数据交给工作台统计。工作台对类型/状态/日期做**容错归一化**，字段缺失用安全默认值，明确非法值按无效行跳过。

- **机器可读标准**：`docs/work_dashboard_data.schema.json`（JSON Schema draft-07，可用于程序校验）。
- **推送方式**：`POST /api/push` + 请求头 `X-Api-Key: <对接码>`，见 `docs/数据对接API.md`。

---

## 1. 顶层结构

```json
{
  "app": "WorkDashboard",           // 建议固定
  "version": 2,
  "exported_at": "2026-09-01 18:00:00",
  "count": 3,
  "works": [ ... ],                 // 日薪工作记录（可带每日收入）
  "presets": [ ... ],               // 日薪预设（可选）
  "monthly_works": [ ... ],         // 月薪任务（可选，无收入字段）
  "monthly_presets": [ ... ],       // 月薪预设（可选）
  "monthly_settings": [ ... ]       // 月薪收入配置（可选）
}
```

> **数据归到日薪还是月薪，由顶层键决定，与界面当前模式无关**：`works` → 日薪表；`monthly_works` → 月薪表。两套表完全独立，互不干扰。

---

## 2. works（日薪工作记录）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | ✅ | 工作名称，≤100 字 |
| `work_type` | string | 否 | `regular`=常规 / `other`=其他（缺失默认常规） |
| `duration_hours` | number | 否 | 花费时长（小时），≥0 |
| `planned_date` | string | ✅ | 计划完成日期 `YYYY-MM-DD`（可带时间，只取前 10 位） |
| `expected_income` | number | 否 | 预期收入（元），≥0 |
| `notes` | string | 否 | 备注，≤2000 字 |
| `status` | string | 否 | `pending`=待完成 / `done`=已完成（缺失默认待完成） |
| `actual_duration_hours` | number/null | 否 | 实际时长（已完成；缺省回退 `duration_hours`） |
| `completed_date` | string/null | 否 | 完成日期（已完成；缺省回退 `planned_date`） |
| `actual_income` | number/null | 否 | 实际收入（已完成；缺省回退 `expected_income`） |

### 2.1 类型 / 状态取值（中英文 + 别名均可识别）

| 标准值 | 可识别别名 | 缺失默认 | 无法识别时 |
|---|---|---|---|
| `work_type` | `regular` 常规工作 / 日常工作 / `daily` / `routine` / 常规；`other` 其他工作 / 临时工作 / 兼职 / `other_work` / `extra` | `regular` | 该行无效（跳过并提示） |
| `status` | `pending` 待完成 / 未完成 / 进行中 / `in_progress`；`done` 已完成 / `completed` / `finished` / `complete` | `pending` | 该行无效（跳过并提示） |

### 2.2 done 自动回退

只写 `"status":"done"` 而不写实际字段时，系统自动补齐，已完成记录不会从统计中消失：
完成日期 ← 计划日期；实际时长 ← 计划时长；实际收入 ← 预期收入。

## 3. 其它可选表

### presets（日薪预设）
`name`(必填)、`work_type`、`duration_hours`、`expected_income`、`notes`。

### monthly_works（月薪任务 · 无收入字段）
`name`(必填)、`work_type`、`duration_hours`、`planned_date`(必填)、`status`、`actual_duration_hours`、`completed_date`、`notes`。
> 月薪任务**禁止**携带 `expected_income`/`actual_income` 等收入字段。

### monthly_presets（月薪预设 · 无收入字段）
`name`(必填)、`work_type`、`duration_hours`、`notes`。

### monthly_settings（月薪收入台账 · 按月一条）
`month_key`(必填 `YYYY-MM`)、`regular_income`(该月常规收入)、`other_income`(该月其它收入)。
可一次推送多个月份，各月独立并存（跨月调薪互不影响）；同一 `month_key` 视为同一个月。

---

## 4. 判重规则（合并时）

| 数据类型 | 判重键（完全相同视为重复，跳过） |
|---|---|
| `works` / `monthly_works` | `name` + `work_type` + `planned_date` |
| `presets` / `monthly_presets` | `name` + `work_type` |
| `monthly_settings` | 按 `month_key` 判重：该月已存在则不覆盖，缺失月份补录 |

## 5. 可直接照抄的完整模板

```json
{
  "app": "WorkDashboard",
  "version": 2,
  "exported_at": "2026-09-01 18:00:00",
  "count": 3,
  "works": [
    {
      "name": "需求评审",
      "work_type": "regular",
      "duration_hours": 1.5,
      "planned_date": "2026-09-01",
      "expected_income": 300,
      "notes": "客户会议",
      "status": "done",
      "actual_duration_hours": 1.5,
      "completed_date": "2026-09-01",
      "actual_income": 300
    },
    {
      "name": "写周报",
      "work_type": "regular",
      "duration_hours": 0.5,
      "planned_date": "2026-09-01",
      "expected_income": 100,
      "status": "done"
    },
    {
      "name": "整理会议纪要",
      "work_type": "other",
      "duration_hours": 1,
      "planned_date": "2026-09-02",
      "status": "pending"
    }
  ],
  "presets": [
    { "name": "需求评审", "work_type": "regular", "duration_hours": 1.5, "expected_income": 300 }
  ],
  "monthly_works": [
    { "name": "月度运维", "work_type": "regular", "duration_hours": 20, "planned_date": "2026-08-31", "status": "done" }
  ],
  "monthly_settings": [
    { "month_key": "2026-08", "regular_income": 8000, "other_income": 1000 }
  ]
}
```

> 第二条 `写周报` 只写了基础字段 + `status:"done"`，导入后系统自动回填完成日期/实际时长/实际收入。

## 6. 发送方式

### 6.1 文件导入（人工）
把上面 JSON 保存为 `.json` 文件，工作台顶部「⇧ 导入」→ 合并/覆盖导入。

### 6.2 推送接口（程序自动）
```
POST http://<工作台地址>/api/push
Headers: Content-Type: application/json
         X-Api-Key: <对接码>          # 工作台「🔗 对接」弹窗里查看
Body:
{
  "source": "计时软件",               // 识别字段：推送方名称（可选，推荐）
  "pushed_at": "2026-09-01 18:00:00", // 识别字段：推送时间（可选，格式 YYYY-MM-DD HH:mm:ss）
  "data": { ...上方标准结构... }      // 实际要入库的数据
}
```
推送后数据先进入**待审查箱**（缓存，不依赖工作台在线即可接收），工作台顶部「🔗 对接」按钮会出现角标提示，审核确认后以合并模式入库。对接码与推送详情见 `docs/数据对接API.md`。

> **识别字段规则（重要）**：`source`（名称）与 `pushed_at`（时间）仅用于待审查箱的**识别与展示**，随原始推送快照保存，**不进入数据库正式表、不参与任何统计报表**。合并入库时只有 `data` 内的业务数据（works/monthly_works 等）写入正式表。
