# 部署指南

## 方式一：本地运行（开发 / 日常使用）

### 环境要求

- Python ≥ 3.10（推荐 3.11+）
- Windows / macOS / Linux 均可

### 步骤

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动
python -m backend.main
```

浏览器访问 `http://127.0.0.1:8000`。数据保存在项目根目录 `data/works.db`。

### 常用配置

```bash
# 指定端口
PORT=9000 python -m backend.main

# 指定数据库位置
WORK_DB_PATH=/path/to/works.db python -m backend.main

# 首次启动写入演示数据（方便体验）
SEED_DEMO=1 python -m backend.main
```

### 开机自启（可选）

- **Windows**：将 `WorkDashboard.exe` 的快捷方式放入「启动」文件夹（`Win+R` → `shell:startup`），开机自动后台运行并打开浏览器。
- **Linux**：使用 systemd 或 supervisor 托管。

## 方式二：Docker 部署

### 构建并运行

```bash
# 进入项目目录
cd work-dashboard

# 构建镜像
docker build -t work-dashboard .

# 运行（数据持久化到命名卷 work-data）
docker run -d \
  --name work-dashboard \
  -p 8000:8000 \
  -v work-data:/data \
  --restart unless-stopped \
  work-dashboard
```

或使用编排文件：

```bash
docker compose up -d
```

### 数据备份与迁移

SQLite 文件位于卷 `/data/works.db`。备份两种方式：

```bash
# 方式 A：直接复制文件（容器运行时可安全复制）
docker cp work-dashboard:/data/works.db ./backup.db

# 方式 B：通过卷
docker run --rm -v work-data:/data -v $(pwd):/backup alpine cp /data/works.db /backup/backup.db
```

### 更新版本

```bash
docker compose down
git pull   # 拉取新代码
docker compose up -d --build   # 重新构建并启动，数据卷不受影响
```

## 方式三：Windows 可执行文件（exe）

> 推荐个人桌面使用。exe 启动后**没有黑色命令行窗口**，自动打开浏览器，状态栏托盘图标常驻，右键可退出。

### 构建

```bash
# 环境要求：Windows + Python ≥ 3.10（建议使用 3.11+）
cd work-dashboard
build_exe.bat
```

脚本会：安装依赖 → 生成/更新图标 → 安装 PyInstaller → 执行打包 → 输出 `dist\WorkDashboard.exe`（单文件，含全部前端资源与托盘图标）。

### 使用

双击 `dist\WorkDashboard.exe`：

1. **无黑框启动**：后台启动 FastAPI + SQLite 服务，默认端口 8000（可用 `PORT` 环境变量修改）；
2. **自动打开浏览器**：服务就绪后自动打开 `http://127.0.0.1:8000`（可用 `AUTO_OPEN_BROWSER=0` 关闭）；
3. **状态栏托盘图标**：
   - **左键单击 / 双击图标**：打开浏览器页面；
   - **右键图标**：菜单「打开工作台」「退出程序」；
4. **退出程序**：右键托盘图标 → 退出；关闭浏览器窗口并不会停止服务；
5. **单实例**：若重复双击 exe，会自动复用已有实例并打开浏览器，不会启动多个服务；
6. **仅本机访问**：exe 默认只监听 `127.0.0.1`，个人数据不会暴露到局域网；如需局域网其他设备访问，设置环境变量 `HOST=0.0.0.0` 后启动（数据无鉴权保护，请仅在可信网络使用）。

数据与日志位置（均在 exe 同级，自动创建）：

- 数据库：`data\works.db`（升级 exe 时保留 `data` 目录即可无损迁移数据）
- 日志：`logs\app.log`（无黑框时所有日志写入此处，便于排查启动问题）

### 手动打包（不使用脚本）

```bash
# 1. 安装依赖
pip install -r requirements.txt pyinstaller

# 2. 生成图标（如尚未生成）
python tools/make_icon.py

# 3. 打包
pyinstaller --noconfirm work_dashboard.spec
```

打包参数说明见 `work_dashboard.spec`：

- `console=False`：无黑框运行；
- `icon=assets/app.ico`：exe 文件图标；
- `datas` 包含 `frontend/` 与 `assets/`，确保前端资源与托盘图标被打包进单文件 exe。

### 常见问题

| 问题 | 解决 |
| --- | --- |
| 端口被占用 | 修改 `PORT` 环境变量后再启动；重复启动会自动复用已有实例 |
| 看不到托盘图标 | Windows 任务栏右侧「显示隐藏图标」箭头中查找；可拖拽到常驻区 |
| 无法自动打开浏览器 | 检查 `logs/app.log`；默认浏览器未设置时，手动访问 `http://127.0.0.1:8000` |
| 想关闭自动开浏览器 | 启动前设置环境变量 `AUTO_OPEN_BROWSER=0` |
| 360/Defender 拦截 | PyInstaller 单文件 exe 首次运行可能被误报，添加信任即可 |
| 数据文件在哪 | exe 同级 `data/works.db`，建议定期备份 |
| 想改图标 | 替换 `assets/app.ico` 后重新打包，或修改 `tools/make_icon.py` 重新生成 |

## 通用运维

### 备份建议

SQLite 是单文件数据库，直接复制 `works.db` 即为完整备份。建议：

- 每周复制一次到外部存储；
- 大版本升级前先备份。

### 日志

- **本地开发 / Docker**：服务日志输出到控制台（Docker 中可通过 `docker logs work-dashboard` 查看）。
- **Windows exe**：无黑框模式所有日志写入 `logs/app.log`，便于排查启动或托盘问题。

### 资源占用

单进程、个人使用场景内存占用约 30-80MB，可常驻运行。
