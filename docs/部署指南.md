# 部署指南

## 方式一：Windows 桌面程序（推荐个人使用）

### 前置要求
- Windows 10/11
- 无需安装 Python（exe 已打包所有依赖）

### 打包
```bat
build_exe.bat
```
打包完成后产物在 `dist\WorkDashboard.exe`。

> 若 `build_exe.bat` 在依赖检查 / `pause` 处卡住（部分中文 Windows 批处理代码页问题），可直接执行等价的 `python -m PyInstaller --noconfirm work_dashboard.spec`，效果相同且更稳。两种方式都会自动备份并恢复 `dist\data\works.db`，不会丢数据。

### 运行
双击 `dist\WorkDashboard.exe`：
- 自动启动后台服务（默认端口 8000）
- 自动打开浏览器访问 `http://127.0.0.1:8000`
- 系统托盘出现图标，右键可退出或重新打开页面

### 数据位置
- 数据库文件：`dist\data\works.db`（与 exe 同目录）
- 重新打包不会删除已有数据（打包脚本自动备份恢复）
- 如需迁移数据，复制 `data\works.db` 到新目录即可
- ⚠️ **两份库不要混淆**：exe 读取的是 `dist\data\works.db`，而**源码运行**（`python -m backend.main`）读写的是仓库根目录 `data\works.db`——这是两个独立文件。若你的真实数据一直在仓库 `data\works.db`（例如平时从源码开发），首次运行 exe 前需把它复制到 `dist\data\works.db`，否则 exe 会打开另一份（可能为空或过期）数据。可用 `WORK_DB_PATH` 环境变量把两者指向同一文件。详见 [数据库设计 · 数据文件位置与打包保留](数据库设计.md#数据文件位置与打包保留)。

### 退出
- 系统托盘图标 → 右键 → 退出
- 退出后无残留进程

## 方式二：Docker 部署（推荐服务器/多人共享）

### 前置要求
- Docker 20.10+
- Docker Compose v2

### 一键启动
```bash
docker compose up -d
```

访问 `http://服务器IP:8000`。

### 数据持久化
数据存储在 Docker 命名卷 `work-data` 中，容器重建不丢失：
```bash
# 查看数据卷
docker volume ls | grep work-data

# 备份数据库
docker cp work-dashboard:/data/works.db ./works_backup.db

# 恢复数据库
docker cp ./works_backup.db work-dashboard:/data/works.db
docker compose restart
```

### 环境变量
| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `WORK_DB_PATH` | `/data/works.db` | SQLite 数据库路径 |
| `HOST` | `0.0.0.0` | 监听地址（**Dockerfile 已内置 0.0.0.0**，容器内外均可访问；本地直接运行 Python 时默认 `127.0.0.1`） |
| `PORT` | `8000` | 监听端口 |
| `SEED_DEMO` | `0` | 设为 1 时首次启动写入演示数据 |

### 单独构建镜像
```bash
docker build -t work-dashboard .
docker run -d -p 8000:8000 -v work-data:/data --name work-dashboard work-dashboard
```
> 镜像已内置 `HOST=0.0.0.0` 与健康检查，`docker run` 后即可从宿主机/局域网访问，无需额外传 `-e` 参数。

### 离线镜像导入 / 导出
项目根目录附带已构建好的镜像文件 `docker-workplan.tar`，无 Dockerfile 构建环境时可直接加载：
```bash
# 导入镜像
docker load -i docker-workplan.tar

# 导出当前镜像（用于迁移到无网络环境）
docker save -o workplan.tar work-dashboard:latest

# 加载后运行
docker run -d -p 8000:8000 -v work-data:/data --name work-dashboard work-dashboard
```

### 健康检查
镜像内置健康检查，每 30 秒探测 `/api/health`：
```bash
docker inspect --format='{{.State.Health.Status}}' work-dashboard
```

## 方式三：直接运行 Python（开发/调试）

### 前置要求
- Python 3.10 ~ 3.13（**不支持 3.14**，部分依赖无预编译 wheel）
- pip

### 安装依赖
```bash
pip install -r requirements.txt
```

### 启动
```bash
# Windows
set WORK_DB_PATH=data\works.db
set PORT=8000
python -m backend.main

# Linux/Mac
export WORK_DB_PATH=data/works.db
export PORT=8000
python -m backend.main
```

访问 `http://127.0.0.1:8000`。

### 开发模式（自动重载）
```bash
uvicorn backend.main:app --reload --port 8000
```

## 数据备份与恢复

### 界面操作
- 设置页 → 导出数据（JSON / CSV）
- 设置页 → 导入数据（支持 merge 合并 / replace 覆盖）

### JSON 备份格式（v2）
```json
{
  "app": "WorkDashboard",
  "version": 2,
  "works": [...],
  "presets": [...],
  "monthly_works": [...],
  "monthly_presets": [...],
  "monthly_settings": [...]
}
```

### 兼容性
- **旧版备份**（只有 `works` 数组或纯数组）：自动识别并导入到日薪模式
- **新版备份**（含 `presets` / `monthly_*`）：完整导入两套模式数据
- CSV 仅支持日薪工作任务导入导出

## 常见问题

**Q: 端口 8000 被占用怎么办？**
A: 设置环境变量 `PORT=8001` 后重新启动。

**Q: Docker 部署后外部无法访问？**
A: 确认 `HOST=0.0.0.0`，检查服务器防火墙是否开放 8000 端口。

**Q: 打包后数据丢失？**
A: 打包脚本会自动备份 `dist\data\works.db`，打包完成后恢复。如遇异常，检查项目根目录是否有 `_db_backup.tmp`。

**Q: exe 打开后数据是空的 / 是旧数据？**
A: 多半是"两份库"问题——exe 读的是 `dist\data\works.db`，而源码运行读的是仓库 `data\works.db`。把你的真实数据文件复制到 `dist\data\works.db`（覆盖前先备份），或用 `WORK_DB_PATH` 让两者指向同一文件即可。

**Q: 如何从旧版升级？**
A: 先在旧版导出 JSON 备份，安装新版后用 replace 模式导入即可。新版自动兼容旧版备份格式。
