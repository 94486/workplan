# 龙猫工作统计台 — 数据导入格式规范

本文档描述如何构建一份**本系统可直接导入**的数据文件（JSON 优先），供第三方工具（如自研计时软件）导出并导入到工作台进行统计。

- **推荐格式**：JSON（完整保留全部字段）
- **编码**：UTF-8（带不带 BOM 均可，`utf-8-sig` / `gbk` 都能识别）
- **导入方式**：工作台顶部「⇧ 导入」→ 选择文件 → 合并 / 覆盖

---

## 1. 顶层结构（JSON 对象）

```json
{
  "app": "WorkDashboard",          // 建议固定，便于识别来源
  "version": 2,                    // 格式版本号，建议写 2
  "exported_at": "2026-09-01 18:00:00",
  "count": 3,                      // works 条数（非必填，仅参考）
  "works": [ /* 日薪工作记录，核心 */ ],
  "presets": [ /* 日薪预设（可选） */ ],
  "monthly_works": [ /* 月薪任务（可选） */ ],
  "monthly_presets": [ /* 月薪预设（可选） */ ],
  "monthly_settings": [ /* 月薪收入配置（可选） */ ]
}
```

> **旧版兼容**：顶层也可以直接是一个纯数组（即 `[...works...]`），系统会自动当作 `works` 导入。
> 缺省的字段（如没有 `monthly_works`）会被当作空数组处理，不影响其它数据。

---

## 2. works（日薪工作记录）字段规范

这是计时软件导出的**核心数组**，每条对应一项工作。

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `name` | string | ✅ | 工作名称；自动去首尾空格，≤100 字；为空则该行无效 | `"需求评审"` |
| `work_type` | string | 否 | `regular`=常规工作 / `other`=其他工作；中文`"常规工作"`/`"其他工作"`及 `daily`/`routine`/`兼职`/`extra` 等别名也可识别；**缺失默认常规；明确写了但无法识别 → 该行无效** | `"regular"` |
| `duration_hours` | number | 否 | 花费时长（小时），≥0；缺省 0 | `1.5` |
| `planned_date` | string | ✅ | 计划完成日期 `YYYY-MM-DD`（可带时间，只取前 10 位）；为空或非法则该行无效 | `"2026-09-01"` |
| `expected_income` | number | 否 | 预期收入（元），≥0；缺省 0 | `300` |
| `notes` | string | 否 | 备注，≤2000 字 | `"客户会议"` |
| `status` | string | 否 | `pending`=待完成 / `done`=已完成；中文`"待完成"`/`"已完成"`及 `completed`/`finished` 等别名也可识别；**缺失默认待完成；明确写了但无法识别 → 该行无效** | `"done"` |
| `actual_duration_hours` | number/null | 否 | 实际时长（已完成），缺省时见下方回退规则 | `1.5` |
| `completed_date` | string/null | 否 | 完成日期 `YYYY-MM-DD`（已完成） | `"2026-09-01"` |
| `actual_income` | number/null | 否 | 实际收入（元，已完成） | `300` |

### 已完成（status=done）数据的自动回退规则

只写了 `status:"done"` 但没填实际字段时，系统会自动补齐，**避免已完成的记录从统计中消失**：

| 缺失字段 | 自动回退为 |
|---|---|
| `completed_date` | `planned_date` |
| `actual_duration_hours` | `duration_hours` |
| `actual_income` | `expected_income` |

> 因此计时软件最少只需输出 `name` + `planned_date` + `duration_hours` + `status`，就能完整入库并按工时/收入统计。

## 3. presets / monthly_*（可选）字段规范

### presets（日薪预设）
| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 预设名称（必填） |
| `work_type` | string | `regular` / `other` |
| `duration_hours` | number | 时长 ≥0 |
| `expected_income` | number | 收入 ≥0 |
| `notes` | string | 备注 |

### monthly_works（月薪任务，无收入字段）
| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 任务名称（必填） |
| `work_type` | string | `regular` / `other` |
| `duration_hours` | number | 时长 ≥0 |
| `planned_date` | string | 计划日期 `YYYY-MM-DD`（必填） |
| `status` | string | `pending` / `done` |
| `actual_duration_hours` | number/null | 实际时长（done 缺省回退 `duration_hours`） |
| `completed_date` | string/null | 完成日期（done 缺省回退 `planned_date`） |
| `notes` | string | 备注 |

### monthly_presets（月薪预设）
`name`（必填）、`work_type`、`duration_hours`、`notes`。

### monthly_settings（月薪收入配置，单行）
| 字段 | 类型 | 说明 |
|---|---|---|
| `month_key` | string | 对应月份 `YYYY-MM`（如 `"2026-08"`） |
| `regular_income` | number | 该月常规工作收入（元） |
| `other_income` | number | 该月其它工作收入（元） |

---

## 4. 合并导入的判重规则（重要）

「合并导入」会保留现有数据，**完全重复的记录会被跳过**：

| 数据类型 | 判重条件（三者/两者完全相同才算重复） |
|---|---|
| `works` / `monthly_works` | `name` + `work_type` + `planned_date` |
| `presets` / `monthly_presets` | `name` + `work_type` |
| `monthly_settings` | 库中已有配置则**不覆盖**，保留现有 |

> 若三条只差一个字段（例如日期不同），就会被当作新记录新增，而不是覆盖旧的。

## 5. 完整示例（计时软件 → 工作台）

假设计时软件某天导出了 3 条工作（2 条已完成 + 1 条待完成），文件内容如下：

```json
{
  "app": "WorkDashboard",
  "version": 2,
  "exported_at": "2026-09-01 18:00:00",
  "count": 3,
  "works": [
    {
      "name": "需求评审",
      "work_type": "regular",
      "duration_hours": 1.5,
      "planned_date": "2026-09-01",
      "expected_income": 300,
      "notes": "",
      "status": "done",
      "actual_duration_hours": 1.5,
      "completed_date": "2026-09-01",
      "actual_income": 300
    },
    {
      "name": "写周报",
      "work_type": "regular",
      "duration_hours": 0.5,
      "planned_date": "2026-09-01",
      "expected_income": 100,
      "notes": "",
      "status": "done"
    },
    {
      "name": "整理会议纪要",
      "work_type": "other",
      "duration_hours": 1,
      "planned_date": "2026-09-02",
      "expected_income": 0,
      "notes": "明天完成",
      "status": "pending"
    }
  ]
}
```

> 第二条只写了基础字段 + `status:"done"`，导入后系统会自动回填完成日期与实际工时，统计中不会丢失。

## 6. 从计时软件映射的建议

计时软件内部通常记录「会话/时间段」（如 `start`/`end`/`work_seconds`），导出到本系统时建议这样转换：

| 计时软件字段 | 本系统字段 | 处理方式 |
|---|---|---|
| 任务名 | `name` | 直接映射 |
| 日期 | `planned_date` / `completed_date` | `YYYY-MM-DD` |
| 当日累计工时（去休息） | `duration_hours` | 秒转小时：`work_seconds / 3600`，可做 0.5h 取整 |
| 任务是否完成 | `status` | 当天计时结束 = `done`，否则 `pending` |
| （可选）任务单价 | `expected_income` | 无单价填 `0` 即可 |

## 7. CSV 变体（可选）

系统同样支持 CSV，第一行必须是可识别的中文表头（列名可中英混用）：

```
工作名称, 类型, 状态, 计划日期, 花费时长(小时), 预期收入(元), 完成日期, 实际时长(小时), 实际收入(元), 备注
```

类型列填 `常规工作`/`其他工作`，状态列填 `待完成`/`已完成`。文件带 `UTF-8 BOM` 可直接用 Excel 打开。
