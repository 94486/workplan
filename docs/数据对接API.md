# 龙猫工作统计台 — 数据对接 API

本系统提供一套**推送式数据对接接口**：外部程序（如自研计时软件）用「对接码」把统计数据直接推送到工作台，数据先进入**待审查箱**，在工作台确认后再以合并模式入库。相比文件导入，对接方式适合程序间自动同步，且带鉴权 + 人工审查，更安全可控。

---

## 1. 总体流程

```
计时软件 ──(对接码 X-Api-Key + JSON)──▶ POST /api/push
                                            │
                                            ▼
                                      待审查箱（不直接入库）
                                            │
       工作台界面「🔗 对接」────────────────┤
        · 查看待审查数据预览
        · 接收合并（合并模式入库，重复跳过） 或  丢弃
```

- 推送的数据**不会自动入库**，必须先审查后合并。
- 合并沿用与文件导入完全相同的判重规则：日薪 / 月薪工作 = 名称 + 类型 + 计划日期三者全等视为重复，跳过；收入配置不覆盖现有。

---

## 2. 获取对接码

工作台界面点顶部「🔗 对接」按钮，即可看到：

- **对接码**（`X-Api-Key` 请求头）：推送方必须携带
- **推送地址**：`http://<工作台地址>/api/push`
- 可点「重新生成」，生成后旧对接码立即失效

也可通过接口获取：

```
GET /api/push/config
→ { "api_key": "wd_xxx...", "updated_at": "..." }
```

重新生成：

```
PUT /api/push/config        body: { "regenerate": true }
→ { "api_key": "wd_yyy...", "updated_at": "..." }
```

## 3. 推送数据（外部程序调用）

```
POST /api/push

Headers:
  Content-Type: application/json
  X-Api-Key: <对接码>

Body:
{
  "source": "计时软件",                      // 识别字段：推送方名称（可选，推荐）
  "pushed_at": "2026-09-01 18:00:00",        // 识别字段：推送时间（可选，YYYY-MM-DD HH:mm:ss）
  "data": {                                  // 与备份/导入相同的结构（实际入库数据）
    "works": [ ... ],                        // 日薪工作记录（可带收入）
    "monthly_works": [ ... ],                // 月薪任务（无收入字段）
    "presets": [ ... ],
    "monthly_presets": [ ... ],
    "monthly_settings": [ ... ]
  }
}
```

`data` 也支持直接传**数组**（等价于 `{"works": [...]}`）。

> **识别字段规则**：`source`（名称）与 `pushed_at`（时间）仅用于待审查箱的**识别与展示**，随原始推送快照保存，**不写入数据库、不参与任何统计**。合并入库时只处理 `data` 内的业务数据；两个字段均**可选**，不传也可正常推送。

### 3.1 最小示例（curl）

```bash
curl -X POST "http://127.0.0.1:8000/api/push" \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: wd_你的对接码" \
  -d '{
    "source": "计时软件",
    "pushed_at": "2026-09-01 18:00:00",
    "data": {
      "works": [
        {"name": "需求评审", "work_type": "regular", "duration_hours": 1.5,
         "planned_date": "2026-09-01", "expected_income": 300, "status": "done"},
        {"name": "写周报", "work_type": "regular", "duration_hours": 0.5,
         "planned_date": "2026-09-01", "status": "done"},
        {"name": "整理会议纪要", "work_type": "other", "duration_hours": 1,
         "planned_date": "2026-09-02", "status": "pending"}
      ]
    }
  }'
```

### 3.2 响应

```json
{
  "inbox_id": 1,
  "received": 3,
  "invalid": 0,
  "message": "已接收 3 条待审查（无效 0 条），请在「数据对接」中确认后合并"
}
```

### 3.3 错误码

| 状态码 | 含义 |
| --- | --- |
| 401 | 对接码无效或缺失 |
| 400 | 数据格式无法识别 / 未识别到有效记录（缺名称、日期非法、类型或状态无法识别） |

### 3.4 字段容错（与文件导入一致）

- `work_type`：`regular`/`常规工作`/`日常工作`/`daily`/`routine` → 常规；`other`/`其他工作`/`临时工作`/`兼职`/`extra` → 其他；**缺失默认常规**；写了但无法识别 → 该行无效。
- `status`：`pending`/`待完成`/`未完成`/`进行中` → 待完成；`done`/`已完成`/`completed`/`finished` → 已完成；**缺失默认待完成**；写了但无法识别 → 该行无效。
- `planned_date`：`YYYY-MM-DD`，可带时间（只取前 10 位）。
- `status:"done"` 缺实际字段时自动回退（完成日期←计划日期、实际时长←计划时长、实际收入←预期收入）。
- 具体字段定义见 `docs/导入数据格式规范.md`。

## 4. 审查合并（工作台内操作）

推送后数据进入待审查箱，可在工作台「🔗 对接」弹窗中：

- **查看与核验**：每条待审查数据展示**来源名称、推送时间、有效条数、无效条数**与两类预览 —— ① 统计摘要（类别构成 / 总工时 / 收入 / 常规·其他 / 日期范围）；② 明细预览（类别标签 / 名称 / 类型 / 日期 / 状态 / 时长 / 收入，按日期排序，**最多前 20 条**，超出时提示「共 N 条，预览前 20 条」）。预览只显示会被入库的有效记录，无效记录（缺名称 / 日期非法 / 类型或状态无法识别）以橙色提示标出「无效 N 条」，让你在接收前就看清这批数据的质量与归属；
- **接收合并**：以合并模式写入正式表，结果反馈**日薪 / 月薪归属明细**（如「已合并 4 条（日薪工作 2 条、月薪任务 1 条、收入配置 1 条），无效 1 条」），重复记录自动跳过；
- **丢弃**：不入库，删除该批数据；
- **全部接收**：一键合并所有待审查数据，同样返回日薪 / 月薪 / 预设 / 收入配置的分类汇总。

对应接口（本地界面调用，无需对接码）：

```
GET  /api/push/inbox                     // 待审查列表（含 record_count 有效数 / invalid_count 无效数 / 有效记录预览）
POST /api/push/inbox/{id}/approve        // 接收合并 → {merged, skipped, invalid, daily_works, monthly_works, ...}
POST /api/push/inbox/{id}/discard        // 丢弃 → {ok}
```

### 只读查询（其它设备读取数据）

`GET /api/push/query` — 用**同一对接码**（`X-Api-Key`）只读查询工作台数据（日薪/月薪任务、预设、收入配置），支持 `scope` / `from` / `to` / `status` 过滤，返回与导出一致的 JSON，可直接作为推送 `data` 回传。参数、响应结构与调用示例见 [docs/数据查询规范.md](数据查询规范.md)。

### 数据归属确认（日薪 / 月薪）

- 数据归到哪套模式由**顶层键**决定：`works` → 日薪表（含每日收入），`monthly_works` → 月薪表（无收入字段），与界面当前处于哪个模式无关，两套表完全隔离；
- 文件导入与推送合并的返回都带 `daily_works / monthly_works / daily_presets / monthly_presets / settings` 分类计数，结果提示也会明示「日薪工作 X 条・月薪任务 Y 条」，方便核对数据是否进对表。

## 5. 安全说明

- 默认服务只监听 `127.0.0.1`，外部无法访问；若需让局域网内程序推送，启动时设置 `HOST=0.0.0.0`（需自行评估暴露风险）。
- 对接码通过 `X-Api-Key` 携带，服务端用常量时间比较校验；重新生成后旧码立即失效。
- 推送数据先审查后入库，任何未经确认的数据都不会污染正式数据。
- 审查接口（inbox/approve/discard）仅用于工作台本地界面操作。
