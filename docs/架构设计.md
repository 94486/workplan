# 架构设计

## 技术栈

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 后端 | Python 3.10+ / FastAPI / Uvicorn | 异步 Web 框架，自动生成 OpenAPI 文档 |
| 数据库 | SQLite（标准库 sqlite3） | 单文件本地存储，零配置，支持事务 |
| 前端 | 原生 HTML / CSS / JavaScript（ES2020） | 零第三方依赖，SVG 自绘图表 |
| 桌面集成 | PyInstaller + pystray + Pillow | Windows exe 打包，系统托盘常驻 |
| 容器化 | Docker / docker-compose | 服务器部署可选 |

## 数据模型

> 本节给出表与字段的概览；完整 DDL、索引清单、设计决策与权衡、迁移策略，以及数据文件位置与打包保留规则，详见 [数据库设计](数据库设计.md)。

### 日薪模式表

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `works` | id, name, work_type, duration_hours, planned_date, expected_income, notes, status, actual_duration_hours, completed_date, actual_income, created_at, updated_at | 工作任务 |
| `presets` | id, name, work_type, duration_hours, expected_income, notes, created_at, updated_at | 录入预设（按 work_type 独立） |

### 月薪模式表（与日薪完全隔离）

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `monthly_works` | id, name, work_type, duration_hours, planned_date, notes, status, actual_duration_hours, completed_date, created_at, updated_at | 工作任务（无收入字段） |
| `monthly_presets` | id, name, work_type, duration_hours, notes, created_at, updated_at | 录入预设（独立于日薪预设） |
| `monthly_settings` | id, month_key, regular_income, other_income, updated_at | 月度收入配置（月薪收入口径来源；`total_income` 由后端计算返回，不落库） |

> **关键设计**：月薪模式只是薪资以月度统计，任务管理/视图/工时趋势仍按周维度运作。两套模式的数据库表完全分离，切换模式不会互相影响数据。

### 数据对接表

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `push_config` | id, api_key, updated_at | 对接码（`X-Api-Key` 鉴权，可重生成，旧码立即失效） |
| `push_inbox` | id, payload, record_count, status, received_at, merged_at | 待审查箱：`payload` 存完整推送 JSON 快照（含 `source`/`pushed_at` 识别字段与 `data`），未经审查确认不写入正式表；识别字段不建独立列、不入统计 |

## 数据对接流程

```
外部程序（计时软件等）
   │  携带 X-Api-Key 对接码 POST /api/push（JSON，字段与文件导入容错一致）
   ▼
后端校验对接码（常量时间比较）→ 校验数据有效性
   │  无效记录标记 skipped（不影响有效记录）
   ▼
进入待审查箱 push_inbox（status=pending，不直接入库）
   │  界面「对接」弹窗提示有 N 批待审查
   ▼
用户在界面「待审查」逐条 / 「全部接收」→ POST /api/push/inbox/{id}/approve
   │  以合并模式入库（复用与文件导入一致的规整/判重逻辑，重复自动跳过）
   ▼
写入正式表（works / monthly_works / monthly_settings，按归属确认）
```

- 归属规则：`works`→日薪表、`monthly_works`→月薪表、`monthly_settings`→收入配置，与界面当前所处模式无关。
- 审查接口返回接收明细（实际入库 / 跳过重复 / 判为无效），可丢弃整批。
- 推送方只需对接码 + JSON，无需登录；对接码可从「对接」弹窗查看 / 重生成。
- **只读查询**：`GET /api/push/query` 用同一对接码（`X-Api-Key`）查询工作台数据（日薪/月薪任务、预设、收入配置），支持 `scope` / 日期 / 状态过滤，返回与导出一致的 JSON；只读不修改数据，规范见 [docs/数据查询规范.md](数据查询规范.md)。

## 前端架构

### 双模式数据隔离（store.js）

```
Store
├── mode: 'daily' | 'monthly'   // 当前模式，localStorage 记忆
├── data.daily: { works, summary }
├── data.monthly: { works, summary, settings }
├── getWorks()      // 返回当前模式的任务列表
├── getSummary()    // 返回当前模式的统计摘要
├── setMode(m)      // 切换模式并通知订阅者
├── refresh()       // 重新拉取全部数据
└── subscribe(fn)   // 订阅数据变更
```

### 模块通信

- `api.js`：唯一的 HTTP 层，所有后端调用集中封装
- `store.js`：数据中心，持有当前模式的数据，提供订阅机制
- `kanban.js` / `stats.js` / `modal.js`：视图层，订阅 store 变更，写操作后调用 store.refresh()
- `app.js`：入口，初始化各模块，绑定全局事件（标签页、主题、模式切换、彩蛋）

### 主题系统

- CSS 变量驱动，`:root` 默认深色，`[data-theme="light"]` 覆盖浅色变量
- 主题状态记忆在 localStorage，切换时设置 `document.documentElement.dataset.theme`
- 所有颜色、边框、阴影通过变量引用，切换无闪烁

## 实时同步机制

任何写操作（新增/编辑/删除/完成/重开）完成后：
1. 调用对应 API
2. 调用 `Store.refresh()` 重新拉取当前模式全部数据
3. Store 通知所有订阅者（看板、统计、列表）重渲染
4. 三视图自动保持一致，无需手动刷新

## 安全设计

- 默认监听 `127.0.0.1`，仅本机访问；Docker 部署时设 `HOST=0.0.0.0`
- 数据存储在本地 SQLite，不上传任何外部服务
- exe 打包后数据在 `dist/data/works.db`，打包脚本自动备份恢复，不会因重新打包丢失
